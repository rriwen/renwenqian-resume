## 写在前面

在传统 Web 开发流程中，产品经理撰写 PRD，设计师交付 Figma 静态稿和设计说明，前端工程师负责将设计“翻译”为代码。这种线性模式往往伴随着巨大的信息损耗：交互状态缺失、动态逻辑模糊、像素级偏差，以及由此引发的沟通与返工。

生成式 AI 正在重塑这一协作范式。设计师不再只是静态图片的传递者，而是更结构化地定义设计意图。Figma 设计稿和需求文档依然重要，但它们逐渐变成研发过程中的辅助探索工具，而不是唯一的交付终点。

本文结合实际项目，分享三类典型场景下的 AI 驱动设计工作流：

- **官网（D0 / M0）**：强营销属性，侧重品牌调性与视觉冲击；
- **新产品（M0 产品）**：没有历史包袱，功能逻辑相对简单，侧重平稳快速落地；
- **成熟产品（OB Cloud 迭代）**：逻辑复杂且拥有设计系统，侧重一致性与工程可维护性。

## 一、官网：定义风格并快速落地

D0 / M0 官网的挑战，是在两周内以最低成本完成品牌视觉探索，并实现从概念到高保真原型的快速闭环。这里既要追求视觉的“美”，也要极致压缩周期。

### 1. 视觉风格探索

传统流程通常是收集素材、制作情绪板、手动绘制多版高保真稿。一旦方向偏差，修改成本就会迅速上升。

AI 辅助让这个过程变成并行探索：

- **概念发散**：输入品牌关键词、行业属性和参考图，同时生成多种视觉风格与页面布局；
- **规范总结**：用 Google Stitch 生成视觉稿，并辅助整理 DESIGN.md 设计规范；
- **规范复用**：将颜色、字体层级、间距和组件规则作为 Prompt 上下文交给 Cursor，约束后续生成。

强营销网站仍然需要一个有记忆点的“视觉锤”。AI 生成的视觉产物往往趋于平均值，因此核心创意仍应由设计师主导。例如，用极具极客感的 ASCII 码表达形成独特的品牌记忆点。

### 2. 内容视觉细化

确定视觉风格后，将 Stitch 页面、视觉锤参考和 DESIGN.md 一起交给 Cursor，核心工作分成两部分：

- **页面框架布局**：读取设计参考和规范，根据内容结构生成页面骨架；
- **首屏视觉锤实现**：把确定的 ASCII 图案做成可复用的小工具，支持随机字符生成、SVG 形状参考和出场动画，并在 D0 与 M0 之间复用。

### 3. 微动效增强

静态页面往往缺乏感染力。借助 AI，可以直接用自然语言描述交互效果，例如：

- ASCII 图案通过随机字符加载出场；
- 鼠标 Hover 时呈现微弱的手电筒打光效果；
- 标题以打字机效果出现。

当没有固定的设计意向时，也可以让 Cursor 调用成熟的动效库，例如 React Bits 的文字动画组件。AI 负责完成集成，设计师负责判断动效是否服务于内容和品牌。

### 4. 重构和复用

D0 / M0 项目还需要持续治理设计复用：

- 及时更新 Cursor Rules，把反复出现的要求和问题转化为规则；
- 要求 AI 定期重构，避免填空式生成带来冗余代码；
- 及时提炼 Design Tokens 和按钮、输入框等通用组件。

在后续项目中，只要把这些规则、组件片段和页面框架提供给 Cursor，就能实现跨项目复用。

## 二、新产品：从用户路径开始

M0 管理后台的重点不是一开始就追求视觉精度，而是先建立产品雏形，打通前后端联调，再基于设计规范更新界面。

### 1. 用户路径设计

可以直接用 Figma Make 对话描述业务场景，例如：“创建一个记忆管理列表，包括记忆的更新时间和内容，支持复制、删除、批量删除和搜索。”

AI 能快速生成低保真原型。这个阶段应该聚焦信息架构和用户路径，而非像素细节。逻辑确认后再进入高保真设计，可以显著降低试错成本。

### 2. 弥补逻辑空白

静态设计稿是“死”的，原型是“活”的。加载、空、错误、权限、键盘交互等状态，往往在传统交付中被遗漏。可以把这些隐形设计转化成自然语言：

- 列表为空时显示引导用户创建第一条数据的空状态；
- 数据加载超过 2 秒时显示骨架屏，而不是无信息的旋转 Loading；
- 上下方向键切换，空格或回车键选中或取消选中。

在 Cursor 中启用 Plan 模式，先要求 AI 生成状态机或流程图，推演网络中断、权限不足等边界，再执行代码生成，能显著提升实现的健壮性。

### 3. 接口自动化对接

对于逻辑相对简单的产品，可以将后端接口和联调要求交给 Cursor：

1. 先让 AI 帮助生成接口联调提示词；
2. 提供接口定义、认证方式和预期交互；
3. 让 AI 执行联调，并根据错误日志修复问题。

设计师不必独立承担全部工程细节，但应该理解接口状态如何影响用户路径。

### 4. 代码重构优化

官网和产品侧往往由不同小组并行启动，容易产生品牌割裂。可以在 Cursor 中执行两类治理：

- 从官网提取已验证的颜色、文字和间距 Token，在产品侧语义 Token 中合并优化；
- 明确规定所有颜色必须引用 Design Token，严禁硬编码 Hex 值。

这样既能保持品牌基因一致，也能让后续主题和组件维护更加稳定。

## 三、成熟产品：高保真还原与工程闭环

OB Cloud 已经拥有成熟设计系统和复杂业务逻辑，重点不再是从无到有，而是高保真还原、交互细腻度和代码可复用性。

### 1. 关键页面构思

设计师可以利用组件库快速搭建关键页面，真正需要解决的是设计属性与代码属性之间的认知差异。

通过 Figma Code Connect，可以将设计组件与前端代码组件库建立一对一映射。按钮、表格和表单在 Figma 中展示的属性，直接对应代码中的真实参数。这样能消除“设计稿看起来是这样，但代码不知道怎么传参”的问题，也让 AI IDE 更准确地使用已有组件。

### 2. 交互细化执行

成熟产品中，设计工作的大量时间用于交互细节、状态流转和极端情况。Cursor 生成的代码往往缺少项目特定的反馈方式和组件布局约束，因此需要调用团队共同维护的设计 Skill。

一个有效的设计 Skill 应包括：

- 全局样式和 Design Tokens；
- 工程安装与目录约束；
- 布局要求和组件使用规则；
- Loading、Empty、Error、Focus 等状态；
- 完成后的检查清单。

执行时，可以让 AI 依据 Skill 自动生成，也可以选中初步生成的代码，让 AI 进行 Token 覆盖、状态补齐和组件替换。

### 3. 代码优化重构

AI 生成的代码需要持续人工介入，常见的工程优化包括：

- **一致性**：检查组件规范，替换硬编码值并调用已有组件；
- **逻辑补齐**：自测并检查边缘情况；
- **冗余清理**：拆分过大的组件，合并重复逻辑。

AI 可以加速修改，但是否应该抽象、怎样抽象，仍然需要设计师和工程师共同判断。

### 4. 代码反哺设计文档

开发过程中经常会产生新的交互逻辑和边缘情况，如果不及时记录，设计原型就会逐渐落后于线上产品。

一个重要的闭环步骤是：根据最终实现的交互逻辑，让 AI 生成更新后的交互说明文档，并同步回设计规范。这样可以解决“文档滞后”问题，为下一次迭代提供准确基准。

## 写在最后：AI 让设计更快地发生

AI 对工作流的影响不只是效率提升，更是设计产生方式的转变。

传统模式下，设计是缓慢的线性制造过程：构思、绘图、标注、等待开发、验收、返工。每个环节都在消耗时间，每次反馈都伴随着延迟。

在 AI 驱动的新工作流中，设计变成一种即时发生的流动状态：

- **想法即刻可视化**：借助 Stitch，风格探索从“天”级缩短到“分钟”级；
- **设计即刻工程化**：依托 Figma Code Connect 与成熟组件库，设计稿可以映射为结构化代码；
- **交互即刻可感知**：联动 Figma Make 与 Cursor，静态界面能在秒级转化为可点击、可感知的真实代码。

AI 加速了从设计意图到实现的过程，让我们有更多时间思考用户需求、梳理业务逻辑和打磨情感化体验。设计师的价值不会因此消失，而是更靠近判断、取舍和对最终体验负责。
