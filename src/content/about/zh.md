## 项目经历

### AI 智能问数

> 产品设计师

> 2025.06-至今

项目背景：在 AI Native 协作模式下，智能问数产品从技术验证进入商业化探索。早期产品虽然能够生成 SQL 和数据报表，但准确性、解释性和结果可信度不足，用户对 AI 结果的采纳意愿较低。

项目目标：提升 AI 结果的可理解性、可干预性和可信度，推动产品快速从内部验证走向商业化交付。

我主要负责：
- 主导 Agent 对话与数据报表生成体验，设计从问题输入、意图识别、指标确认、任务执行到结果反馈的完整人机交互链路；
- 围绕问数失败节点，协同优化语义解析、指标与维度匹配、时间范围识别、工具路由和 SQL 结果校验，降低自然语言到数据结果的转换损耗；
- 设计任务状态、执行步骤、异常反馈、结果解释和人工干预机制，让用户能够理解 Agent 的进度、调用工具、数据来源和生成依据；
- 基于客户反馈定位 Agent 执行链路问题，独立孵化 Agent 可观测产品，建立任务追踪、节点状态、工具调用、异常定位、耗时分析和结果评估能力。

业绩：
- 通过优化语义解析、指标匹配、工具调用、结果校验和反馈机制，推动 AI 结果用户采纳率从 15% 提升至 60%；
- 推动产品从技术验证、内部试点进入商业化落地，完成 5+ 家付费客户交付；
- 从用户反馈中识别共性问题并孵化 Agent 可观测产品，支撑后续问题定位和效果迭代。


### AI 设计工程化

> 负责人

> 2025.09-至今

项目背景：随着团队和产品规模扩张，设计规范、组件资产与前端实现之间缺少统一的协作和验收机制，导致设计还原、组件复用和视觉验收依赖人工沟通。

项目目标：建立从设计规范、组件代码到 AI 生成和视觉验收的统一协作链路，提升设计研发效率和实现一致性。

我主要负责：
- 建立 Design Token 体系，统一颜色、字体、间距和圆角等基础变量，制定命名、分层和使用规则；
- 基于 Figma Code Connect 梳理组件、变体和交互状态，建立设计组件与代码组件的映射关系；
- 建设组件库 Skill 和 DESIGN.md，沉淀组件属性、使用场景、页面结构、布局规则、响应式要求和交互约束，适配 AI Native 研发流程；
- 设计自动化视觉验收流程，建立视觉基线、比对规则和问题反馈机制，并协同设计、前端团队完成试点落地和持续迭代。

业绩：
- 打通“设计规范—组件代码—AI 生成—视觉验收”链路，形成统一的设计研发协作流程，覆盖 5+ 团队设计研发交付；
- 通过自动化视觉验收，将单次验收时间从至少 2 人天缩短至分钟级。


### 数据开发产品

> 体验设计师

> 2022.01-2024.06

项目背景：数据库运维平台希望实现「三步五分钟」的自助化体验，但用户下单、数据迁移、开发变更审批等核心链路仍大量依赖技术支持，自助率仅 15%；多个数据开发编辑器交互不一致、视觉陈旧，影响开发效率和用户留存。

项目目标：将核心链路自助完成率提升至符合「三步五分钟」目标，降低技术支持成本；同时提升编辑器矩阵的体验一致性、专业度和用户满意度。

我主要负责：
- 通过用户体验地图和埋点数据诊断各场景的自助率与业务影响，确定数据迁移、编辑器标准化等多期优化优先级；
- 协调产品、设计、研发资源，以设计冲刺方式在一周内完成核心任务流程重构方案和用户测试，推动方案进入开发排期；
- 落地数据迁移步骤串联、对象过滤交互、编辑器矩阵标准化和暗黑模式等关键模块，并建立埋点看板支持后续迭代决策。

业绩：
- 核心链路自助完成率从 15% 提升至 75% 以上，技术支持成本降低 20%；
- 产品矩阵用户满意度从 4.8 提升至 6.2（7 分制），用户数翻倍增长；
- 形成「数据洞察 → 方案验证 → 埋点闭环」的产品决策机制，沉淀为团队标准化工作方法。
